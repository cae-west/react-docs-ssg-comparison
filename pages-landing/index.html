Summary

Docusaurus came closest to react.dev, MkDocs Material was the fastest on desktop, and GitBook was the quickest to publish but the hardest to bend to react.dev's look. All three serve the complete, unmodified React documentation: 225 pages, the five react.dev sidebars and 322 images.

No tool could render react.dev's custom MDX components (Sandpack editors, callouts, diagrams) on its own. Each needed an adapter: theme components in Docusaurus, a build hook in MkDocs, and a pre-build script that writes a converted copy for GitBook. The content files themselves were never edited.

Setup experience

GitBook was quickest to a first published page; Docusaurus and MkDocs each needed real work before any page was readable.

Docusaurus. The project scaffold installed in about 22 seconds with one prompt, and a build takes 40–80 seconds. Pointed at the content, 218 of 225 pages crashed, because react.dev's custom tags (Sandpack, Note, DeepDive and others) are undefined outside react.dev. Defining stand-ins for them in the theme fixed every page.

MkDocs Material. It needs Python and a virtual environment, and on Python 3.15 PyYAML had no prebuilt wheel, so the install needed a workaround. The first build reported 0 errors, but pages were garbled: MkDocs reads Python-Markdown, not MDX. It also only builds files inside its docs folder, so images had to be added in a hook.

GitBook. Setup is an account, a space and a Git Sync connection to the repository, with no local tooling. Git Sync failed twice on config (it wanted gitbook-docs.yaml, and both the section and the space had to be marked default). The first import then took about 5 minutes. GitBook is a paid hosted product, used here on a 14-day trial.

Navigation structure

Docusaurus and MkDocs reproduce react.dev's four-part navigation; GitBook folds everything into one sidebar. All three were driven from react.dev's own sidebar files, so the page order and section headers match react.dev everywhere.

  • Docusaurus puts Learn, Reference, Community and Blog in the top bar and shows only that section's sidebar, as react.dev does. Breadcrumbs and a nested "On this page" list sit beside each page.
  • MkDocs Material shows the same four sections as tabs under the header, plus Home. Its table of contents nests down to code-file headings on the tutorial.
  • GitBook has no top-level tabs, so Learn, Reference and the React DOM sections all stack in one long sidebar. "On this page" lists only top-level headings: 4 on the tic-tac-toe tutorial and 3 on useState. Page URLs come from sidebar group titles (/react-19.3/hooks/usestate), not react.dev's paths.

Broken in-page links after the fixes: Docusaurus 26 anchors on 15 pages, MkDocs 24, GitBook 33 on 15 pages. Nearly all come from react.dev's own content, such as links to pages its site generates in code.

Customization

Docusaurus can run react.dev's own code; MkDocs can imitate it; GitBook can only be themed.

Docusaurus. Because it is built on React, it ran react.dev's real homepage component, with Tailwind, 13 files copied from react.dev and two small stand-ins for Next.js modules. Custom tags became styled React components, and a remark plugin fixed image paths and heading ids at compile time.

MkDocs Material. A Python hook rewrites each page as it builds: it reads the sidebars, converts heading ids, turns custom tags into styled blocks and fixes links and images. Templates and one CSS file carry react.dev's fonts and colors. The homepage had to be a static HTML copy of react.dev's, so its interactive demos are pictures.

GitBook. There is no custom CSS, JavaScript or plugin system. Styling is limited to theme settings, colors and icons, plus GitBook's own blocks, which built a react.dev-style homepage from the same text and code. Every content fix had to happen before GitBook saw the files, in a script that writes a converted copy (217 of 225 files changed).

None of the three could reproduce react.dev's live Sandpack editors, YouTube embeds or error decoder.

Performance

MkDocs Material is the only site rated good, at 98 on desktop; on mobile the three score 61–66, a gap within normal run-to-run variation.

Docusaurus loses desktop points to JavaScript that blocks the page for 1.6 seconds while React takes over the static HTML. GitBook is slowest to show the main content on mobile (7.0 s). MkDocs ships the least JavaScript, which shows in its desktop numbers.

Developer experience

Docusaurus tells you what broke; MkDocs often does not; GitBook gives you nothing to debug locally.

  • Docusaurus stops on a broken page with an error naming the missing component, and lists every broken link and anchor at the end of a build. Its log looks alarming (20 lines mention "error"), but those were harmless HTML-minifier notes. Local search only works after a production build, not in the dev server.
  • MkDocs Material builds 225 pages in 18–70 seconds with built-in search. It fails silently: unconverted MDX built with 0 errors, and pages titled <textarea> blanked every page until titles were escaped. The dev server does not watch template overrides.
  • GitBook has no local build. Problems surface only after a sync, as dead links in the published site (1,943 before the conversion script). Git Sync is two-way, so changing a setting in GitBook's editor commits to the repository under your name.

Publishing to a GitHub Pages subfolder broke images in both static generators: about 55 raw <img> tags and the homepage images used root paths. Each needed a small fix to apply the base path.

Ease of use

For a writer, GitBook is easiest; for a developer maintaining react.dev-style content, Docusaurus is easiest once set up.

  • GitBook needs only a browser. Writers can edit pages in its editor, and the sidebar is one SUMMARY.md file. The catch is that MDX-heavy content like React's has to be converted first, and keeping that converted copy in sync is a manual step.
  • MkDocs Material keeps everything in one readable mkdocs.yml plus a hook file. Adding a page is a Markdown file and a nav entry, but non-standard Markdown needs Python to handle.
  • Docusaurus asks the most up front: Node, React components, and knowing which theme files to override. After that, new content written in MDX works as react.dev's authors intended.

Overall presentation

Docusaurus is the most faithful copy of react.dev, MkDocs a close second, and GitBook looks like GitBook.

  • Docusaurus matches react.dev's header, centered search, homepage and callout boxes, with react.dev's fonts and code colors. A reader could mistake its pages for react.dev.
  • MkDocs Material matches the pages closely: same fonts, green Note callouts, filename labels on code. Its header and tab bar keep Material's layout, and the homepage's grey band is boxed to the content width rather than running edge to edge.
  • GitBook is clean and readable but plainly a GitBook site: its own header with an "Ask" AI button, "Was this helpful?" and a "Powered by GitBook" badge. react.dev's Note callouts appear as plain paragraphs, and the homepage is an ordinary docs page with the sidebar still showing. In Firefox and Waterfox, the header icon and site title don't render, though they do in Chrome and Edge.

Method and sources

  • Content: react.dev's src/content (225 Markdown/MDX files), its five sidebar files and public/images (322 images), copied unmodified from reactjs/react.dev.
  • Versions: Docusaurus 3.10.2 (Node 22), MkDocs 1.6.1 with Material 9.7.7 (Python 3.13), GitBook hosted with Git Sync, October 2026.
  • Rule kept: no content file was edited. Docusaurus and MkDocs adapt the content while building; GitBook reads a converted copy generated by gitbook/build.py.
  • Performance: PageSpeed Insights (Lighthouse), one run per URL on October 16, 2026: Docusaurus, MkDocs Material, GitBook.
  • Screenshots: light mode. Docusaurus and MkDocs at 1440 × 900 in Chromium; GitBook in Waterfox, scaled to the same width.
