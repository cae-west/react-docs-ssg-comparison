# React Docs in Three Static Site Generators

The complete [React documentation](https://react.dev) (225 pages) rebuilt in three documentation tools, to compare how each one structures, presents and runs the same content:

| Tool | Live site |
|---|---|
| **Docusaurus** 3.10 | https://cae-west.github.io/react-docs-ssg-comparison/docusaurus/ |
| **MkDocs Material** 9.7 | https://cae-west.github.io/react-docs-ssg-comparison/mkdocs/ |
| **GitBook** (hosted) | https://react-docs-1.gitbook.io/react-docs |

The comparison write-up (setup, navigation, customization, performance, developer experience, ease of use, presentation, with screenshots and Lighthouse results) is on the landing page: https://cae-west.github.io/react-docs-ssg-comparison/

> The GitBook site runs on a trial plan and may go offline after about Oct 30, 2026.

## The rules

- **Do not modify the content.** `content/` is an unmodified copy of react.dev's `src/content`. Every fix lives in a tool's own config, plugins or build scripts.
- Focus on how each tool presents and structures the docs.
- Make each site look as close to react.dev as the tool allows.

## What the comparison found

- **Out of the box, none of the tools handle react.dev's MDX.** Docusaurus crashed on 218 of 225 pages (undefined custom tags). MkDocs built with zero errors but rendered garbled pages. GitBook imported everything but left 1,943 links dead and `{/*id*/}` in every heading.
- **Each needed a different kind of fix:** theme components and a remark plugin (Docusaurus), a Python build hook (MkDocs), a pre-build script that writes a converted copy (GitBook, which has no plugin system).
- **Performance (PageSpeed Insights, `useState` page, mobile / desktop):** Docusaurus 64 / 70, MkDocs Material 66 / 98, GitBook 61 / 79. Mobile scores are a tie within run variance; MkDocs is clearly fastest on desktop.
- **Not reproducible in any tool:** live Sandpack editors, YouTube embeds, the error decoder, Algolia search and the version badge. These are react.dev application code, not content.

See the landing page for the full write-up.

## Repository layout

```
content/          Unmodified copy of react.dev src/content (225 .md files)
sidebars/         react.dev's 5 sidebar JSON files (Home, Learn, Reference, Community, Blog)
public/images/    322 images from react.dev public/images
docusaurus/       Docusaurus site (reads ../content in place)
mkdocs/           MkDocs Material site (config + hooks.py + theme overrides)
gitbook/          GitBook content, generated by gitbook/build.py (do not hand-edit)
gitbook-docs.yaml GitBook Git Sync config
pages-landing/    Landing page and write-up for GitHub Pages
.github/workflows/pages.yml   Builds Docusaurus + MkDocs and deploys to GitHub Pages
```

## Run locally

### Docusaurus

Requires Node 22.

```bash
cd docusaurus
npm install
npm run build
npm run serve
```

Search only works after `npm run build` + `npm run serve`, not `npm start`.

### MkDocs Material

Requires Python 3.

```bash
cd mkdocs
python -m venv .venv
.venv/Scripts/python -m pip install mkdocs==1.6.1 mkdocs-material==9.7.7
.venv/Scripts/mkdocs serve
```

On macOS/Linux use `.venv/bin/` instead of `.venv/Scripts/`. Open http://127.0.0.1:8000/. On very new Python versions, if the PyYAML install fails, prefix the install command with `PYYAML_FORCE_LIBYAML=0`.

### GitBook

GitBook is hosted, so there is nothing to serve locally. Regenerate its content from the repo root:

```bash
python gitbook/build.py
```

GitBook syncs from the `main` branch via Git Sync (configured in `gitbook-docs.yaml`).

## Deployment

Pushing to `main` runs `.github/workflows/pages.yml`, which builds Docusaurus and MkDocs with sub-path base URLs and publishes them with the landing page to GitHub Pages. GitBook cannot be hosted there.
